## 1. What P3.1a is, and what it is not

**Is:** a measurement increment establishing what the request-decision stage actually does, what
evidence exists for it, and how much real traffic that evidence represents.

**Is not:** enforcement, shadow activation, behavior change, global certification, or P3.2.

**The increment succeeds if it produces honest measurements, including unfavourable ones.** A
result showing the rules are unreachable, the corpus unrepresentative, or the benefit smaller than
assumed is a successful P3.1a and a legitimate input to stopping at P3.3.

## 3. Deliverable A — rule inventory and actual-stage exercise

### A1. Enumerate from BASE, without trusting the enumeration

Produce a declared-rule inventory from the **BASE** tree: each rule definition, its identity, and
its claimed source/family applicability pairs.

The "nine question-only rules" figure came from static predicate inspection, and 3 of 9 declare
`source` non-literally. **The inventory's location is not assumed.** Candidate sites —
`lib/query-guidance.ts`, `lib/refusal-safety.ts`, `lib/capability-policy.ts`,
`lib/source-capabilities.ts`, `lib/geo-guidance-lite.ts` — are **starting points, unverified**;
the enumeration reports what it found, not a confirmation of this list.

### A2. The observation stage must call production predicates, not copy them

The CANDIDATE observation stage **calls or imports the same predicate functions used by request
handling.** A reimplementation would measure the test rather than the system — the exact error
class that took seven rounds to remove from the P2.5 guard.

**Proved by a mutation control, not asserted:** changing an underlying production predicate must
change **both** the request-path result and the observation-stage result. A candidate whose
observation result is unaffected by that mutation is a duplicated test-only predicate and is
**rejected** (stop condition §10.2).

### A3. Mechanical divergence stop rule

Revision 1 said "materially differs", which is circular. Execution **stops and returns to the
owner** on any of:

1. an observed rule identity absent from the frozen inventory;
2. a declared rule with no executable production predicate binding;
3. a claimed applicability pair for which no positive control can fire;
4. a source/family pair emitted at runtime but absent from the frozen applicability map;
5. a decision/reason pair outside the typed admissibility contract (`isAdmissiblePair`);
6. an ambiguity preventing assignment of exactly one accountable rule result.

Other `declared-but-unexercised` cases are reported **without stopping only if** the frozen
contract classified them in advance as expected-negative or unreachable **and gave the reason**.

### A4. Report every state separately

`exercised-as-declared`, `declared-but-unexercised`, `observed-but-undeclared`, `ambiguous`,
`unreachable` — never collapsed into a pass rate. Per case: rule identity, decision, reason code,
source, family, whether the expected rule fired, whether any unexpected rule fired.

**Absence in natural traffic never establishes unreachability.** Only deliberate exercise does, and
only for the predeclared inputs.

## 4. Deliverable B — certification evidence, frozen before execution

### B1. Reuse only within pinned scope

Corpus v0.1 and rubric v1 are evidence **only for RTCI** at their pinned artifacts — not for
NIBRS, SHR, Historical, or the embed surface.

### B2–B4. Coverage map, minimum cases, case record

A versioned rule-evidence coverage map: rule × source × question family × expected disposition ×
evidence status, every cell covered-by-existing, covered-by-new, or **uncovered and named**. For
each named gap the minimum adjudicated cases — one positive, one false-acceptance, one
false-refusal — plus triggering and non-triggering cases for every claimed applicability pair. No
expansion beyond named gaps.

Every case carries: stable identity, verbatim question, expected disposition, independently
established expected evidence where an answer is required, required caveat or reason class,
applicability, pinned artifacts. Confirmed defects are preserved permanently as regressions.

### B5. Freeze and hash before any execution

The complete case set, rubric, expected evidence and applicability map are **frozen and hashed**
before the stage is exercised or the corpus run (§12 step 4). The hash is recorded in the report.

**If runtime exercise reveals an undeclared rule or an inadequate case, stop and write a new
frozen version.** A case is never added to an already-observed run.

### B6. Honest accounting

Every unrun, blocked, excluded, unresolved and unrepresented case is reported as such. A case that
could not run is never counted as passing and never silently dropped.

## 5. Deliverable C — representativeness, with an executable privacy boundary

### C1. Predeclaration, complete before any log access

- **Window:** 90 days preceding execution, exact bounds recorded at run time. **90 days is an
  implementation parameter inside the owner-approved D3 measurement**, chosen not derived; its
  limitation is reported.
- **Eligible population — defined mechanically from the pinned schema.** The `query_log` table
  records `tab`, not route identity. The population is therefore defined by `tab` values, and the
  increment **enumerates the distinct `tab` values present in the window as a count-only preflight**
  before mapping them to routes. `tab` is the closest measurable proxy for route provenance and
  **that limitation is named in the report**, not glossed.
- **Pre-outcome rows:** rows with `ts < 1788186010301` predate typed outcomes, lack the outcome
  columns, and are counted and reported **separately**.
- **Repeats:** raw and deduplicated counts both reported.
- **Taxonomy:** source, question family, geography grain, period, ambiguity, expected-disposition
  applicability. Fixed before classification.
- **Classification:** each row labelled deterministic, manually adjudicated, or **unresolved**.
  Unresolved is a reported category, never forced into a bucket.
- **Sampling:** default is **full count**. A **count-only preflight** — row counts and distinct
  `tab` values only, **no question text read** — may select between the predeclared full-count
  method and a fully specified sampling method whose threshold, seed, ordering, strata and
  denominator treatment are **frozen before any question text is read**.

### C2. Executable privacy boundary — memory-only on production

"Protected local context" is not executable. Before any production access, a **single reviewable
measurement artifact** is written, and an **off-production fixture rehearsal** must prove the
properties below.

**MEMORY-ONLY ON PRODUCTION.** Revision 2 allowed a transient raw-bearing file on the production
host, root-owned `0600` inside a `0700` directory. That contradicted this contract's own §8 and
§10: **creating that directory or file is itself a production mutation**, and the governing
authorization permits only a read-only measurement. The corrected rule:

1. Production question rows are processed **in memory only**, by the exact reviewed artifact
   **streamed to the host at invocation** — never installed, copied, or written there. No part of
   the artifact persists on production.
2. **No production file or directory is created, changed, renamed or deleted** — not temporary,
   raw-bearing, aggregate-only, script, log, status, cache, bytecode, or evidence. This includes
   any V8/Node compile cache; the artifact runs with compile caching disabled and writes nothing to
   any cache path.
3. **stdout carries aggregate and label-only output** plus bounded non-secret execution metadata.
   **stderr is likewise raw-free** — no rejected row, no exception object carrying question text.
4. Deterministic classification is distinguished from unresolved. **"Manual" classification either
   uses a separately authorized non-agent protected interface, or the row is left unresolved** —
   an agent-operated shell is not a protected adjudication interface.
5. **The transient-file lifecycle and crash-recovery rules apply only to the off-production fixture
   rehearsal**, where such files may legitimately be used to test crash and leak handling. They do
   not authorize anything on production.
6. A **sentinel fixture** proves a known raw value cannot be found in stdout, stderr, durable
   output, or any rehearsal artifact.
7. **If execution cannot remain memory-only on production, stop and return to the owner** rather
   than creating a protected host file. There is no fallback that writes to production.

Promoting a minimized raw question into a permanent regression case still requires separate
justification recorded with its authority.

### C3. Two numbers, never one

Report separately: (1) correctness within the certified denominator; (2) the fraction and
composition of eligible production traffic that denominator represents. Unclassifiable and
unrepresented traffic named explicitly. Neither may stand in for the other — a substitution I made
once already in the Phase 2 checkpoint.

## 6. Deliverable D — proved read-only production access, one snapshot

A `SELECT` does not prove the database was untouched. The measurement artifact must:

1. **prove the live database identity from the running application** rather than assume the
   documented path;
2. open through an **explicitly read-only mechanism**, enabling query-only behavior where
   supported;
3. issue **no** checkpoint, backup, journal-mode assignment, schema change, temp-table creation, or
   application request;
4. use **bounded busy/operation timeouts** and stop rather than contend materially with production;
5. capture **existence, device/inode, size, nanosecond mtime, mode, owner and SHA-256** for the
   main file **and every present sidecar**, before and after, requiring **exact equality**;
6. treat a sidecar appearing or disappearing as **mutation**, unless the predeclared live-engine
   model demonstrates why that comparison is invalid **and supplies a stronger safe check**;
7. verify the database path and the schema the classifier needs **before any raw row is selected**;
8. **fail closed with aggregate-only output**;
9. **write nothing to the host** — see §5.2. The artifact is streamed at invocation and leaves no
   file, directory or cache behind.

### D1. One consistent read snapshot

The count-only preflight, the denominator and the classifications must describe **the same 90-day
population**. The measurement therefore uses **one explicitly read-only, query-only SQLite read
transaction/snapshot for all population counts and row classification**, under the predeclared
bounded timeout.

**If a consistent snapshot cannot be held without materially blocking live writers, stop.** Counts
drawn from different database states are never combined and reported as one denominator.

This does **not** relax the exact before/after file-and-sidecar checks above. Natural production
writes may cause a conservative stop; they may never be silently attributed or waived.

**A pinned fact to re-verify, not assume:** production was recorded at P2.3 preflight as
`journal_mode=delete`, which implies no `-wal`/`-shm` sidecars in normal operation and makes a
read-only open unlikely to create one. The artifact **re-verifies the journal mode read-only at
execution** and treats a different mode as a predeclaration failure, not as a detail to absorb.

P3.1a does **not** close on an uncommitted local guard. The normal landing sequence applies:

1. local contract, mutation, accounting, flags-off and checkout-sensitive checks;
2. **Codex review of the exact CANDIDATE and its evidence**;

**The 30-case data-backed run is not a hosted-CI requirement** — its protected substrate and

## 10. Stop conditions

1. **Inventory divergence** under the mechanical rule (§3.3).
2. **Duplicated predicate** — the observation stage does not move with a production predicate
   mutation (§3.2).
3. **Privacy breach** — raw question text reaching any artifact outside the protected boundary, or
   any sentinel-fixture failure (§5.2).
4. **Read-only violation** — any before/after mismatch under §6.
5. **Post-hoc authoring or tuning** — cases or rubric changed after results (§4.5).
6. **Any production mutation**, attempted or accidental. **This explicitly includes creating any
   file, directory or cache on the production host, however transient, however restrictive its
   permissions** (§5.2).
7. **Memory-only infeasible** — if production classification cannot run without writing to the
   host, stop and return to the owner. There is no write-to-production fallback (§5.2.7).
8. **No consistent snapshot** — if one read-only snapshot cannot cover counts and classification
   without materially blocking live writers, stop rather than combine states (§6.1).
9. **Pin drift** — BASE, CANDIDATE, substrate or evidence artifacts changing mid-increment.
10. **Scope expansion** beyond §3–§9.
11. **An unresolved concrete weakness named in self-review** (§11).

## 11. Self-review, and the owner confirmations Revision 1 wrongly re-asked

Under the standing rule, a concrete weakness named here is a stop condition, not a disclosure.

**Corrected from Revision 1:** I asked the owner to re-confirm three items that the 2026-09-01
decision had already settled. **All three are resolved by that decision and are not re-asked:**

- the 90-day window is an implementation parameter inside the D3-approved measurement — kept, with
  exact bounds and limitation reported (§5.1);
- D2 approved one predeclared off-production corpus run; **the model calls it requires are already
  in scope** (§7);
- the owner approved P3.1a knowing it is a measurement increment, so W6 is **already accepted**.

A new owner decision is required only for material scope expansion, a named stop condition,
production mutation or activation, or progression to P3.2.

**Open weaknesses, each resolved in-contract:**

**W1 — I do not know where the rule definitions live.** The corpus reason classes did not appear in
the obvious `lib/` modules on the pinned tree. *Resolved:* §3.1 makes enumeration the first task and
forbids treating the candidate list as verified; §3.3 stops on divergence.

**W2 — corpus v0.1 may barely exercise these rules.** It was built for answer correctness, not rule
triggering. *Resolved:* §4.2's coverage map makes the overlap visible as uncovered cells; §4.3
authorizes exactly the minimum new cases. Near-zero overlap is a P3.3 finding, not grounds to
expand scope.

**W3 — the current-tree run may not reproduce 5/30.** Model non-determinism alone may move it.
*Resolved:* §7 separates harness/model from semantic failures, preserves the old baseline, and
declares the run a measurement rather than a gate.

**W4 — `tab` is a proxy, not route identity.** The schema has no route column. *Resolved:* §5.1
defines the population mechanically on `tab`, requires a count-only preflight enumerating distinct
values, and requires the limitation to be named in the report.

**W5 — "manual adjudication" has no protected interface today.** I do not have a non-agent
interface for reading raw questions. *Resolved:* §5.2.4 makes that explicit — without such an
interface, rows are **left unresolved** rather than adjudicated through an agent shell. Unresolved
rows are reported, and this will likely reduce classifiable coverage. That reduction is the honest
outcome, not a problem to work around.

**W7 — memory-only classification may not be achievable.** Revision 2 assumed a protected host file
was available; §5.2 now forbids it, and I have not yet demonstrated that classification of a
90-day population can run entirely in memory on the host, streamed at invocation, with compile
caching disabled and nothing written. *Resolved as a stop, not a workaround:* §5.2.7 and §10.7
require stopping and returning to the owner if it cannot. There is deliberately no fallback that
writes to production, because the fallback is what created this contradiction in the first place.

**W8 — one snapshot may conflict with not blocking live writers.** Holding a single read
transaction across counts and classification is what makes the denominator coherent, but a long
read on a `journal_mode=delete` database can contend with writers. *Resolved as a stop:* §6.1
requires stopping rather than either blocking production or stitching counts from different
states. Which of those two constraints binds first is unknown until measured, and I am not
assuming it will be the convenient one.

**W6 — this increment adds no answer correctness.** *Accepted by the owner* (§11 above), recorded
so it is never later described as a correctness gain.
